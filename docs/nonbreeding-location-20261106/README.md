# 보호종 비번식 관찰 위치 공개 변경안

아래 초기 검토는 시작 HEAD 2a2a9ca의 기록이다. 후속 성능·전환 결과와 최소 운영 메타데이터 읽기는 [다음 단계 검증](PREDEPLOY_VALIDATION.md)을 따른다.

기준 main: `e05f725557986934aea8fe167b766f7e82f6a948` (2026-11-06).
요청: 매(Falco peregrinus)를 포함한 보호종도 **비번식이 확인된 관찰**은 기존 공개 조건 아래 표시한다. Draft 검토용이며 main 병합·Worker 배포·운영 DB 조회/수정은 수행하지 않는다.

## 조사 결과

- `shared.js:isSensitiveReport()`는 기존 보호종 19종과 번식 표현으로 공개를 제한한다. 한글 `매`는 포함하지만 학명·괄호 병기 별칭은 빠져 있었다.
- 정본 접수의 `quickInput()`은 `non_breeding_confirmed === true`를 요구한다. 확인은 변경 불가능한 `raw_submissions`의 `non_breeding_confirmed=1`, `policy_version='non-breeding-v1'`, 원입력에 이미 저장된다. 화면은 `/reports/capabilities`를 확인한 뒤 확인란을 켠다. 초기 false와 legacy 형식은 유지한다.
- 확인 근거가 공개 조회에 전달되지 않아 검색은 보호종을 일괄 가렸다. 반대로 승인 마커와 지점·탐조지 이력은 번식/미확인을 재검사하지 않아 승인 또는 연결만으로 위치가 공개될 수 있었다.
- `checklists.raw_id`와 원자료 출처는 불변이다. 정본 스키마는 정확한 해시로 검사되므로 새 열/테이블을 만들지 않고 기존 증빙을 읽는다. 스키마·마이그레이션·운영 설정 변경은 없다.

## 적용 정책과 보안 영향

| 기록 | 공개 위치 처리 |
|---|---|
| 명시적 비번식 확인 + 일치하는 원자료 + 보호종 | 기존 pending 공개 설정/승인 상태에 따라 표시 |
| 위 조건 + 위치 가리기 | 기존에 저장된 동일한 대략 좌표만 표시 |
| 번식·둥지·새끼·포란·육추 등 긍정 증거 | 종·체크박스·승인 상태와 무관하게 위치 비공개 |
| 보호종이지만 확인 누락/false/잘못된 형식/legacy 자료 | 미확인으로 유지, 위치 비공개 |
| 원자료와 종·실제 좌표·관찰일·메모가 달라진 보호종 | 기존 확인을 재사용하지 않고 미확인으로 처리 |
| 일반종의 기존 미확인 기록 | 비번식으로 분류하지 않으며, 번식 증거가 없으면 기존 공개 정책 유지 |

확인은 **제보자가 기존 확인란에서 명시적으로 한 선언**이다. 전문가의 현장 검증을 의미하지 않는다. 시즌·지역·종 이름·메모에 번식 표현이 없다는 이유만으로 비번식을 추정하지 않는다. 기존 자료의 확인을 보충하는 관리자 기능이나 일괄 backfill은 추가하지 않는다.

현재 메모와 원자료의 번식 표현을 우선 검사한다. `비번식`/`non-breeding`이라는 문자 자체는 긍정 번식 증거에서 제외하지만, 이것만으로 비번식을 확인하지 않는다. `비번식, 둥지`처럼 긍정 신호가 함께 있으면 차단한다. 어휘 기반 검사이므로 부정문 `둥지 없음`도 보수적으로 차단하며, 모든 동의어·오입력·허위 신고를 판별하는 생물학적 검증은 아니다. 보호종 전체 분류 체계를 확대하지 않고 기존 목록과 매의 정확한 학명/영문명/괄호 병기/수량 별칭을 다룬다.

공개 판정은 approved/pending 마커, 검색의 이동 대상·탐조지명·지역, 연결/고정점 이력, 탐조지 이력, 재전송 접수 응답과 상태 표시에 적용한다. 탐조지 이력은 가려진 행을 건수·페이지 계산 전에 제외한다. 위치 가린 연결 이력도 정확한 부모 위치에 붙이지 않는다. 검색의 종·날짜 및 동의한 이름은 기존 공개 범위를 유지하되 제한된 기록의 위치 대상은 내보내지 않는다.

원자료와 실제 좌표는 서버 내부 판정에서만 읽는다. 응답에는 원입력·메모·IP 해시·관리자 메모·확인 증빙을 추가하지 않는다. 이름 공개 동의, 기존 위치 가리기, CAPTCHA, 중복 방지, 관리자 인증, 공개 권한의 primary snapshot/5초 상한과 변경 감지는 유지한다. 공개 projection 버전은 화면과 API 모두 `nonbreeding-location-v2`로 올려 이전 정책 응답과 새 정책 응답을 구분한다. 추천 가점과 기여자의 종 목록은 기존의 보수적 보호종 제외 정책을 유지한다.

## 검토할 한계와 향후 승인된 배포 조건

- 탐조지 이력은 비공개 행이 total/페이지에 섞이지 않도록 해당 탐조지의 승인 행을 먼저 읽고 필터링한다. 큰 이력이 누적되면 전송/메모리 비용을 측정하고 별도 최적화해야 한다. 전체 제보를 읽는 것이 아니라 기존 site 인덱스로 해당 지역을 제한한다.
- 관리자 편집으로 확인 근거가 달라진 보호종은 다시 비공개가 된다. 기존 미확인 기록을 공개하려면 확인 근거를 검토하는 별도 절차가 필요하다.
- 공개 projection 버전을 화면/API에 함께 반영한다. 구버전 화면은 새 버전을 거부하고 보유 위치를 지우며, 새 화면도 구버전 API를 거부한다. 같은 epoch/revision에서도 정책 버전 불일치로 자료가 제거되는 회귀 검사를 추가했다. 향후 승인된 조정 배포에서 화면과 Worker의 버전 일치와 열린 기존 화면의 제거 동작을 확인해야 한다. DB epoch/revision을 수동 변경할 필요가 없으며 이번 작업에서 배포는 수행하지 않는다.
- CI 통과와 최종 사용자 승인 전에는 main 병합·운영 배포하지 않는다. PR은 Draft로 유지한다.
