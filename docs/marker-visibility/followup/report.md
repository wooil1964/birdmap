# PR #62 링 애니메이션 후속 검증

2026-11-01 KST · 작업 브랜치 `codex/marker-visibility-pc-mobile` · main 병합 및 운영 배포 없음.

## 수정과 실제 Chrome 관찰

`assets/birdmap-markers.js`의 pulse circleMarker 선 투명도를 0에서 1로 수정했다. CSS는 요소 전체의 opacity를 바꾸므로 기존 SVG `stroke-opacity="0"`에서는 두 반복 모두 선이 그려지지 않았다. CSS의 900ms × 2 설정은 유지했다.

실제 설치된 Google Chrome 156에서 첫 반복 약 225ms·두 번째 반복 약 1125ms에 요소가 연결되어 있고 `opacity × strokeOpacity > 0.05`이며 링이 확대되어 있음을 검사했다. 900ms에는 `animationiteration`, 1800ms에는 `animationend`가 발생하고 pulse가 제거되며 고정 링은 남는다. 따라서 `animationend {once:true}`는 첫 반복에서 제거하는 결함이 아니며 유지했다. 움직임 줄이기에서는 pulse 없이 고정 링·10% 확대만 표시한다.

원래 e2112의 마커 JS만 주입한 음성 대조 검사는 두 반복 모두 strokeOpacity=0으로 실패했다. 최초 293개 검사가 CSS/DOM 조건만 확인해 놓친 실제 그리기 결함을 새 검사가 잡는다. 종료 이벤트 대기는 샘플링 전에 등록해 느린 브라우저에서도 이벤트를 놓쳐 대기가 멈추지 않게 했다.

[한 장 비교](comparison.png) · [실시간 마커 검사](marker-result.json) · [수정 전 실패 증거](before-negative-result.json) · [같은 위상 화면 측정](visual-evidence.json)

캡처는 실제 OSM·VWorld 지도 타일을 읽고 제보·GPS는 합성 자료를 사용했다. 동일한 그림을 비교하려고 캡처에 한해 애니메이션을 225ms·1125ms에 일시 정지했다. 반복·종료 시점과 제거는 별도 실시간 검사 결과다. 모바일 상세 패널은 유지했고 지도를 이동해 마커가 보이는 위치로 촬영했다. 초기 선택 위치를 패널이 가리는 기존 배치는 남아 있다.

추가 반복 실행의 568×320에서는 기존 팝업 자동 이동 뒤 원본 출현종과 pulse가 함께 Leaflet 표시 범위 밖으로 나가 두 SVG 경로가 `M0 0`으로 비워지는 경우도 확인했다. 이 경우를 눈에 보인다고 세지 않는다. 검사는 원본도 폭 0·빈 경로·`_empty()` 상태인 경우에만 기하 크기 0을 허용하며, 선 투명도와 애니메이션 확대는 두 반복 모두 반드시 검사한다. 원본이 그려지면 pulse도 실제 확대 폭이 있어야 한다. 원본의 위치/상세 패널 배치는 변경하지 않았다.

GPS·브라우저 보안 검사는 합성 자료/로컬 타일을 사용하며 운영 요청·외부 non-GET은 0이다. Python의 기존 skip은 공식 조석 표본 날짜가 이동 월간 범위 밖이라는 조건이며 새 skip을 추가하지 않았다. 자세한 결과는 [CI 감사](evidence/ci-audit/CI-AUDIT.md), [감사 요약](evidence/ci-audit/audit-summary.json), [전면 회귀 로그](evidence/regression/front.log), [브라우저별 종료 상태](evidence/regression/summary.json)에 있다.

지도 장애 전체 첫 실행의 `wide wheel_flicks_uneven_per_ip_limit`은 1920×1080에서 타일 요청 129·오류 33 뒤 OSM 잠금으로 실패했다. 기준 df90011의 같은 장면은 PC 통과·wide 동일 실패(1 통과/1 실패)로 정확히 재현됐다. 현재 코드의 단독 재실행은 PC·wide 모두 통과(2/2, wide 타일 요청 90·오류 0)했다. 이는 기준에서도 재현되는 시점/부하에 민감한 기존 실패다. 재실행 성공으로 전체 첫 실패를 덮지 않았으며 관련 지도 구현은 수정하지 않았다.

## 기존 실패와 별도 발견된 계약 문제

주간 추천 실패 이름·오류·기준 SHA와 새 실행 로그를 유지했다. 612행은 `0 !== 3`, 1799행은 `null.rankScore`, 1873행은 예상 ID 대신 빈 배열이다. 기준 df90011과 현재의 실패 이름이 정확히 같다. 모의 가을 월과 실제 11월 날짜를 함께 쓰는 기존 fixture 불일치이며 추천 구현·테스트는 이번 작업에서 변경하지 않았다. [기준 새 로그](evidence/ci-audit/baseline-weekly-rerun.tap)

별도 후속 Python 실행에서 원래 PR e2112의 HTML 계약 검사 9건 실패도 발견했다. 이는 기존 실패로 숨기지 않았다. 기준 df90011의 해당 32건은 모두 통과했다. PR의 정확한 마커 연결/팩토리/갱신 4개 HTML 변경만 역변환하는 엄격한 정규화를 추가해 해결했다. 전체 HTML이 기준과 정확히 일치하는지, 누락·중복·부분 변경·변조는 거부하는지, 보안·좌표·ID 변경이 계속 드러나는지를 새 3개 검사로 확인했다. 기존 보안 검증을 없애거나 넓은 예외를 추가하지 않았다. 새 검사는 CI Python 목록에도 포함했다.

## GitHub 상태와 병합 판단

[원래 Actions 실행](https://github.com/wooil1964/birdmap/actions/runs/41257408265)의 `gps-browser`는 성공했다. `regression`은 전면 회귀에서 실패했고, 뒤 8–20단계는 skipped였다. 후속 API·보안·D1 검사가 당시 실행된 것처럼 보고하지 않는다. 이번에는 후속 검사를 배포 없는 로컬 경로로 각각 실행했다. GitHub artifact 업로드 자체는 로컬 검사로 대체하지 않았고 원래 실행에서는 skipped다.

최신 커밋의 원격 CI 결과 및 지도 장애 검사 최종 결과는 아래 최종 상태에 별도로 기록한다. 로컬 성공이 원격 check를 녹색으로 바꾸지는 않는다.

## 남은 위험

- 기존 주간 추천 3건으로 전체 CI는 녹색이 될 수 없으며, 별도 후속 지도 검사에서도 기준 재현되는 wide 실패 1건이 남았다. 해당 문제를 해결하거나 저장소 정책에 따른 별도 판단이 필요하다.
- 작은 모바일의 기존 상세 패널 가림은 유지했다.
- 모바일은 설치된 Chrome의 터치 에뮬레이션이며 물리 기기 Safari는 확인하지 않았다.
- 현재 상태는 수정 검토 가능이나 즉시 병합 준비 완료로 판정하지 않는다.

사용자의 최종 승인 전 main 병합·운영 배포를 수행하지 않는다.
