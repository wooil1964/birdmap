# 중부권 탐조지 10곳 추가

대상은 ID 196–205: 비내섬·비내길, 보강천·미루나무숲, 무심천·체육공원,
속리산 법주사·세조길, 탑정호 수변생태공원, 봉선저수지·물버들길,
대호호·대호방조제, 황구지천·수원 황구지교, 청미천·장호원체육공원, 강천섬·남한강변.
삽교호는 포함하지 않는다.

`data/central-birding-sites-20261018.json`에 검토한 좌표, 공개 출처, 종 목록과 조사 범위를 보관한다.
지도 핀은 권역을 방문하기 위한 대표 위치이며 종별 출현 위치·둥지·실시간 소식이 아니다.
팝업의 탐조 팁에서도 이 차이를 안내한다. 비내섬의 민감종 세부 위치는 추가하지 않는다.
국립생물자원관 2024–2025 동시센서스는 권역 기록으로 사용하며, 속리산은 2020년 공원사무소 발표,
비내섬은 공개 습지 조사, 강천섬은 2026년 관찰자의 공개 기록을 사용한다.

기존 v21·v24 엑셀에는 이 10곳이 없음을 확인했다. 기존 엑셀을 임의 수정하지 않고,
이번 추가분의 검토 원본을 별도 JSON으로 보존한다. 기존 190개 런타임 레코드는 전체 필드가 동일해야 한다.
지도와 기상 Worker의 ID·이름·좌표·환경·선상 여부를 대조한다. 신규 10곳은 내륙이므로 조석 연동 대상이 아니다.
공유·검색 페이지와 기상 파일은 기존 생성기로 생성한다. 기상 생성은 키 없는 기존 Open-Meteo 대체 경로로
200곳 모두 성공했으며, 기상 자료를 수동으로 채우지 않았다.

## 운영 적용

1. 전체 CI와 실제 Chrome의 10곳 검색·마커·출현종·지도 링크 검증을 통과한다.
2. 기상 Worker의 기존 설정·비밀키를 보존하여 사이트 목록만 확장한다.
3. 운영 D1의 `sites` 190개 및 `system_state`를 읽기 전용으로 보관한다.
4. `prepareSiteSeed`에 `expectedCount:200`을 명시하여 현재 런타임으로 계획을 만들고 ID 196–205만 선택한다.
   기존 seed 도구의 기본값·기존 운영 전환 기능은 수정하지 않는다.
5. `append-registry.sql`에 확인한 generation, 기존 190개 레코드 JSON, 신규 10개 레코드 JSON을 바인딩한다.
   정확한 기존 레코드 전체 일치, NORMAL 상태·generation 일치, 신규 ID·개수·중복 검사를 모두 만족할 때만
   단일 원자적 INSERT로 추가한다. 불일치·재실행은 오류로 중단한다.
6. 기존 190개 전체 레코드의 해시가 동일하고 신규 10개가 계획과 같으며 외래키 오류가 없음을 확인한다.
   관찰·제보·승인·공개 권한 테이블과 스키마는 변경하지 않는다. 해당 Worker도 배포하지 않는다.
7. Pages 병합·배포 후 모바일·PC 크기의 실제 Chrome에서 200곳과 신규 10곳을 확인한다.

SQLite 회귀시험은 실제 적용 SQL을 사용하며, generation 불일치, 기존 레코드 변경, ID 중복·누락·미검토 ID,
유지보수 상태에서 전체 변경이 중단되는지 검증한다. 원격 실행 전 native local D1에서도 검증한다.
과거 190곳 고정 추천 비교는 동일한 과거 입력·190개 전체 레코드 및 추천 결과 서명을 그대로 검사하고,
새 10곳은 별도의 출처·좌표·검색·팝업 시험으로 검사한다.
