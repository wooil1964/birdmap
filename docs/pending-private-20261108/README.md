# 승인 전 제보 위치 비공개 수정 (2026-11-08)

## 변경 범위

- 모든 pending 제보는 공개 좌표와 마커를 반환하지 않는다. 과거 pending_public=1, 실제 좌표와 같은 approx_*도 예외가 아니다.
- 최초·재전송·중복 UUID 재생 접수증은 상태 필드만 허용한다. 과거 불변 원자료의 accepted.spot은 수정하지 않고 응답에서 제거한다.
- visibility(public=true/1)는 거부한다. 반려·공개 취소·위치 가리기 수정 후에도 대기 공개를 복구할 수 없다.
- 기존 approve/link 승인 절차, 보호종 위치 판정 v2, 승인 검색·이력·길찾기 로직은 유지한다. 일반종 자동 공개는 추가하지 않는다.
- 마이그레이션과 기존 행 재분류는 없다. 운영 승인 133건은 이전 감사의 기준 수치이며 이번 작업에서 운영 D1을 쓰지 않는다.

## 공개 계약

projection은 nonbreeding-location-v2-pending-withheld-v1이다. 위치 정책 v2의 판정 함수는 그대로이며, 대기 보류 정책 추가를 구 화면이 감지하도록 식별자를 바꾼다. 서버와 Pages의 식별자가 다르면 기존 fail closed 동작으로 공개 표시를 닫는다. 따라서 향후 승인된 반영에서는 두 Worker와 Pages의 버전 정합을 확인해야 한다. 구 화면은 새 계약을 받으면 대기 레이어·팝업·캐시를 지우며, 새 화면도 잘못 도착한 대기 DTO를 표시하지 않는다.

## 검증

- reports-api: 접수/재생/상태, 기존 공개 플래그, 관리자 가림/재공개 거절/승인/반려/공개 취소/연결, 승인 후 v2·검색을 메모리 내 SQLite로 검증한다.
- pending-private.test.mjs의 같은 노출 재현 시험을 수정 전 고정 소스와 수정 후 소스에 각각 실행하여 전자는 실패, 후자는 차단 통과를 확인한다.
- 화면 전환 시험은 실제 구 legacy·v2 소스를 고정 Git 커밋에서 읽고, 동일 epoch/revision의 정책 전환·만료·지연 응답·BFCache 복원을 검증한다.
- 기존 PR CI의 서버·Chrome·검색·GPS·길찾기·자료 계약 검사를 그대로 실행한다. 최종 실행 수치와 결과는 PR에 기록한다.

## 실패·복귀 원칙

이번 변경 후에도 기본 운영은 접수 pending → 관리자 approve/link → approved인 기존 승인제다. 자동 공개 상태나 별도 데이터 전환이 없으므로 승인제로 돌아가기 위한 DB 역변환은 없다. 오류가 나면 미처리 제보는 pending으로 보존하고 관리자가 기존 승인 절차로 처리한다.

향후 승인된 운영 반영에서 복구가 필요하면 **대기 비공개 차단을 포함한 검증된 버전**으로 복구한다. 예전 취약 버전이나 REPORTS_PENDING_PUBLIC=1만으로 되돌리지 않는다. 정합성을 확인할 수 없는 동안에는 기존 REPORTS_PUBLIC_READS_CLOSED=true 긴급 차단으로 위치 응답을 먼저 닫고, 안전 버전의 Worker·Pages 계약과 승인 자료를 확인한 뒤 공개 읽기를 다시 연다. 이 긴급 차단은 승인 자료 표시도 잠시 중지하므로 적용은 별도 운영 승인에 따른다. 기존 승인 데이터·원자료는 수정하거나 복원 덮어쓰기하지 않는다.

## 잔여 한계

이미 수신·복제된 좌표는 회수할 수 없다. 구 화면 제거는 기존 최대 5초 공개 권한 수명의 한계를 따른다. 기존 v2에서 관리자 승인 후 허용하는 공개 범위는 이번 수정으로 강화하거나 재분류하지 않는다. 운영 반영 전까지 현재 운영 코드의 위험이 제거되었다고 주장하지 않는다.

main 병합·Worker/Pages 배포·운영 설정/D1 변경은 이 PR 작업에서 수행하지 않는다.
