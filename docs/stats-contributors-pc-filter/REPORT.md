# 누적 출현종 목록 · 전체 기여자 · PC 필터 닫기

브랜치 `feat/stats-contributors-pc-filter` (기준 main `c2a3524`, PR #25 병합 후).

## 구현 구분: 기존 데이터·API로 되는 것과 새 API가 필요한 것

| 기능 | 구분 | 이유 |
|---|---|---|
| 1. 누적 출현종 이름 목록 | **새 Worker API 필요** (`/reports/reporter-species`) | 승인 공개 목록(`/reports/approved`)에는 메모가 없어 "번식·둥지" 키워드 제외를 클라이언트에서 할 수 없고, `spot_key`가 끊긴 행은 목록에서 빠질 수 있다. 공개 제한을 서버에서 같은 스냅샷으로 적용해야 한다. |
| 2. 전체 누적 기여자 | **새 Worker API 필요** (`/contributors/all`) | 월별 API는 날짜 범위가 필수다. 승인 공개 목록으로 세면 끊긴 `spot_key` 행이 빠져 월별 합과 어긋날 수 있다. 월별과 같은 SQL에서 날짜 조건만 뺐다. |
| 2-1. 전체 목록 이름 클릭 통계 | 기존 `/reports/reporter-stats`에 `source=all` 증명 추가 | 전체 목록 자체가 이름을 공개하는 투영이므로 같은 증명 규칙으로 허용. 응답은 숫자 두 개 그대로. |
| 3. PC 필터 닫기 | **프런트만** | `index.html`만 변경. |

D1 스키마·마이그레이션·인덱스 변경 없음. 운영 D1·Worker·Pages 배포 없음.

**배포 순서 주의:** 프런트를 먼저 배포하면 새 엔드포인트가 없어 종 목록·전체 기여자가 "불러오지 못했습니다"로 표시된다(공개 정보 노출은 없음). reports-api Worker를 먼저 배포하고 그다음 Pages를 배포해야 한다. 이전 프런트는 새 API를 부르지 않으므로 Worker 선배포는 영향이 없다.

## 1. 누적 출현종 이름 목록

- 통계 모달의 "누적 출현종 수 N종"이 버튼이 된다(N>0일 때). 누르면 같은 모달 안에 종 이름 목록이 열린다.
- 서버(`/reports/reporter-species`): reporter-stats와 **같은 증명**(공개 이력 ID / 월간 목록 / 전체 목록)과 같은 대상(승인 + 이름 공개 동의 + 정확히 같은 닉네임)을 쓴다.
  - 보호종(`SENSITIVE_SPECIES`, 수량 표기 포함), 번식·둥지 키워드가 있는 제보, 위치를 가린 제보는 **행 전체를 제외**(recent-sites와 같은 규칙).
  - 응답은 `{species:[이름…], restricted:boolean}`만. 날짜·좌표·메모·제보 ID 없음.
  - 같은 종명 중복 제거, 가나다(코드 포인트) 정렬.
- 프런트: 응답 키·자료형·중복·제어문자를 엄격히 검사하고, 실패하면 목록을 그리지 않고 "확인할 수 없습니다"만 표시. 다시 정렬하고 검색창으로 부분 검색.
- 제외된 행이 있으면 "보호종·번식 관련 제보와 위치를 가린 제보의 종 이름은 표시하지 않습니다."를 표시. 그래서 목록 종 수는 위 숫자보다 작을 수 있다(숫자는 기존 정의 그대로).

## 2. 이번 달 / 전체 기여자

- 기존 이번 달 집계·요약 상자·`/contributors/monthly`·`?view=contributors&full=1` 딥링크는 그대로.
- '전체 보기'는 이제 인원과 관계없이 표시(전체 기여자로 가는 입구).
- 모달에 '이번 달 / 전체 기여자' 탭과 닉네임 검색창. 전체 기여자는 `/contributors/all?limit=200&offset=…`로 200명씩, 부족하면 '기여자 더 보기'.
- 집계: 승인 + 이름 공개 동의 + 공백 아닌 닉네임, 정확히 같은 닉네임끼리 건수 합산(월별과 같은 정렬: 건수 내림차순 → 이름). 승인 취소·비공개 전환·삭제된 행은 조회 시점에 바로 빠진다.
- 응답은 이름·건수·합계만. 좌표·연락처·종·날짜 없음.
- 페이지가 다른 공개 상태(revision)에서 오면 이어 붙이지 않고 처음부터 다시 받는다.

## 3. PC 전용 필터 닫기

- PC(701px 이상): 필터 패널 오른쪽 위에 '닫기'. 누르면 패널만 숨기고 '☰ 필터 열기'로 초점을 돌린다. 체크박스·검색어는 유지.
- 모바일(700px 이하): 사용자 결정에 따라 기존 버튼·패널·검색을 그대로 두고, '닫기'는 표시하지 않는다.

## P1 보안

- 새 경로 2개는 `publication.js`의 공개 권한 게이트(nonce·expectedEpoch/Revision·같은 primary 스냅샷·no-store) 안에서만 응답한다. 계약 없는 요청은 200을 받지 못한다(시험).
- 프런트는 모두 `publicationFetch`(사전 확인 → 자료 → 사후 확인)를 거치고, `publicationInvalidate` 시 종 목록(`closeReporterStats`)과 전체 기여자(`clearContributors`)를 지운다. Chrome에서 만료 시 목록·모달이 사라지는 것을 확인했다.
- 추천 알고리즘·대안 B는 변경 없음(추천 서명: 190곳·176후보·위치별 점수 동일).

## Worker·D1 부하 (추정)

운영 공개 자료(읽기 전용 확인): 승인 제보 약 64건, 공개 닉네임 18명, 이번 달 승인 24건·기여자 10명.

- 두 기능 모두 **사용자가 누를 때만** 호출한다. 지도 로드·주기 확인에는 요청이 추가되지 않는다.
- 한 번 열 때 Worker 요청 3건(사전 확인 · 자료 · 사후 확인), '더 보기'마다 3건 추가.
- D1: 종 목록은 해당 닉네임의 승인 행만 읽는다(증명 하위 질의 포함). 전체 기여자는 승인 행을 3번 훑는다(전체 수·고유 닉네임 수·목록). 승인 64건이면 한 번에 수백 행 수준.
- Workers Free(일 10만 요청) 기준 하루 1,000번 열어도 3,000요청(3%). D1 Free(일 500만 행 읽기) 기준으로 승인 행이 수천 건이 되어도 여유가 있다. 승인 행이 수만 건 이상으로 커지면 `(status, name_public, reporter)` 인덱스(D1 마이그레이션, 별도 승인)를 검토한다.
- 실제 청구·사용량은 Cloudflare 대시보드에서 확인해야 한다.

## 남은 한계

- 동명이인은 구분하지 않는다(기존 닉네임 기준 정책).
- 전체 기여자 검색은 불러온 쪽 안에서만 한다(200명을 넘으면 '더 보기' 후 검색). 서버 닉네임 검색은 이름 추측 조회를 막기 위해 만들지 않았다.
- 종 목록의 숫자(기존 정의: 모든 승인 동의 제보의 종 수)와 목록 길이는 공개 제한 때문에 다를 수 있다.
