# 전국 탐조지도 SEO 정적 페이지

## 구성

| 파일 | 역할 |
|------|------|
| `sites/<id>/index.html` | 탐조지별 검색용 가이드 (169곳). 스크립트·네트워크 요청 없음 |
| `sites/index.html` | 시·도별 탐조지 목록(허브) |
| `sitemap.xml` | 허브 + 메인 + 가이드 169곳 = 171 URL. `lastmod` 없음 |
| `robots.txt` | 전체 허용 + sitemap 위치 |
| `.github/scripts/build_seo_pages.py` | 위 파일 생성기 (`--check`로 최신 여부 검증) |
| `.github/scripts/test_seo_pages.py` | sitemap·메타·누출 검사 (CI 연결됨) |

탐조지가 바뀌면 `python .github/scripts/build_seo_pages.py` 를 다시 실행해 커밋한다.
자료원은 `index.html`의 `siteData`이며 새 필드를 만들지 않는다.

## 색인 대상 판정 (190곳 중 169곳)

- 같은 이름의 둘째 이후 지점 13곳 제외: 어청도(101~103)·외연도(104~106)·백령도(117~119)·흑산도(127~130).
  제목이 같고 종 목록이 거의 같아 중복 문서가 된다. 지도에서는 그대로 열린다.
- 대표 조류 3종 미만 7곳 제외: 92 공주 금강, 123 광주호호수생태원, 132 용봉습지공원,
  141 연천군 두루미 관람대, 144 송도, 188 이천항, 193 월포리해변. 자료를 보강하면 자동으로 포함된다.
- 제외된 곳은 페이지·sitemap 항목이 없다(`noindex` 페이지를 만들지 않음).

## 개인정보·민감정보

- 정적 페이지는 `siteData`의 일반 항목만 쓴다. 좌표, 제보, 현장소식, 제보자 이름, D1 자료는 읽지도 쓰지도 않는다.
- JSON-LD는 `BreadcrumbList`만 사용하며 `geo`·좌표를 넣지 않는다. 테스트가 좌표 패턴·`<script>`(JSON-LD 외)·`fetch`·`workers.dev` 부재를 페이지마다 검사한다.
- 종 목록은 지도에 이미 공개된 대표 조류다. 멸종위기종이 포함된 탐조지(예: 저어새)가 있으나 위치는 지명 수준이다. 공개하기 곤란한 종·지점이 있으면 알려 주면 목록에서 뺀다.
- `robots.txt`는 보안 수단이 아니다. 비공개 자료는 애초에 정적 파일에 넣지 않는다.
- 기존 `share/<id>/` 미리보기 페이지는 `noindex,follow` 만 추가했다(검색 색인에서 `sites/`와 중복되지 않도록). 공유 링크와 OG 이미지는 그대로 동작한다.

## 중요: robots.txt 위치 한계

크롤러는 **호스트 루트**(`https://wooil1964.github.io/robots.txt`)의 robots.txt만 읽는다.
`/birdmap/robots.txt`는 프로젝트 페이지라 크롤러가 읽지 않는다(해가 없어 요청대로 추가).
따라서 sitemap은 robots.txt가 아니라 **서치 콘솔에 직접 제출**해야 한다.

## 사용자가 해야 하는 일 (배포 후)

1. **Google Search Console**: URL 접두어 속성 `https://wooil1964.github.io/birdmap/` 등록 → 소유권 확인(HTML 파일 업로드 방식: 구글이 주는 `google….html`을 저장소 루트에 두면 됨) → `sitemap.xml` 제출.
2. **네이버 서치어드바이저**: 사이트 등록 → 소유확인(HTML 태그 또는 파일) → 사이트맵 제출. 네이버는 도메인 단위(`wooil1964.github.io`) 등록이라 하위 경로(`/birdmap/`)만 등록되지 않을 수 있다. 이 경우 `wooil1964.github.io` 저장소를 만들어 루트에 인증 파일을 두거나 자체 도메인을 쓰는 방법이 필요하다(서치어드바이저에서 확인 필요).
3. 인증 파일·태그는 발급받은 값이 있어야 하므로 이 PR에 넣지 않았다. 기존 인증 태그는 저장소에 없었다.

검색 순위는 보장되지 않으며, 색인까지 수일~수주가 걸릴 수 있다.

## Cloudflare 비용 영향

가정은 모두 추정이며 실제 청구액이 아니다.

- **검색엔진이 정적 가이드 페이지를 방문**: GitHub Pages 정적 파일만 응답. Worker·D1 요청 **0건**(페이지에 스크립트·외부 요청 없음, 로컬에서 855회 로드 검사).
- **방문자가 "지도에서 열기"로 지도를 사용**: 기존과 동일한 지도 호출이 발생한다. 코드상 주기는 최근 제보 10분, 현장소식 60초, 시작 시 일회성 호출 수 건.
  가정: 세션 평균 3분, 세션당 Worker 요청 약 10건(시작 5 + 현장소식 3 + 제보 갱신 ≈2).

| 검색 유입 방문자 | 추가 Worker 요청(추정) | Workers Paid 포함분(월 1,000만 건) 대비 |
|---|---|---|
| 100명 | ~1,000 | 0.01% |
| 1,000명 | ~1만 | 0.1% |
| 10,000명 | ~10만 | 1% |

포함분 안이므로 요청 과금 증가는 0으로 본다(초과 시 100만 건당 $0.30 가정치). D1 읽기 수는 각 API가 캐시를 쓰는지에 따라 달라 이 작업에서는 측정하지 않았다. Worker·D1 코드는 수정하지 않았다.

## 배포·롤백

- 배포: PR 병합 시 GitHub Pages가 정적 파일을 그대로 서빙한다. 빌드·Worker 변경 없음.
- 롤백: PR을 revert하면 `sites/`, `sitemap.xml`, `robots.txt`, `index.html` 헤드, `share/*` 의 `noindex` 가 함께 원복된다. 이미 서치 콘솔에 제출했다면 sitemap 삭제 후 제거 요청이 필요하다.
- 유의: `index.html` 변경은 `<head>` 메타·JSON-LD와 검색 패널 하단 링크 한 줄뿐이다. 자동 갱신 JSON은 건드리지 않았다.
