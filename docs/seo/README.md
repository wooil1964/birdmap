# 전국 탐조지도 SEO 정적 페이지

## 구성

| 파일 | 역할 |
|------|------|
| `sites/<id>/index.html` | 탐조지별 검색용 가이드 (173곳). 스크립트·네트워크 요청 없음 |
| `sites/index.html` | 시·도별 탐조지 목록(허브) |
| `sitemap.xml` | 허브 + 메인 + 가이드 173곳 = 175 URL. `lastmod` 없음 |
| `robots.txt` | 전체 허용 + sitemap 위치 |
| `.github/scripts/build_seo_pages.py` | 위 파일 생성기 (`--check`로 최신 여부 검증) |
| `.github/scripts/test_seo_pages.py` | sitemap·메타·누출 검사 (CI 연결됨) |

탐조지가 바뀌면 `python .github/scripts/build_seo_pages.py` 를 다시 실행해 커밋한다.
자료원은 `index.html`의 `siteData`이며 새 필드를 만들지 않는다.

## 색인 대상 판정 (190곳 중 173곳, 제외 17곳)

기준: 대표 조류 3종 이상(아래 번식 민감종 제외 후), 지역·환경·추천 시기 존재.
같은 이름의 지점은 서로 다른 장소(0.3~5km 떨어짐)이므로 이름만으로 제외하지 않는다.
종 목록이 이미 만든 같은 이름 페이지와 Jaccard 0.5 이상으로 겹치면 복사본으로 보고 페이지를 만들지 않으며,
대표 페이지에 "지도의 같은 이름 탐조 지점" 링크(`?site=<id>`)로 연결한다.
페이지를 만드는 같은 이름 지점은 제목을 "<이름> 지점 <id>"로 구분한다

## 번식 민감종

`build_seo_pages.py`의 `NEST_SENSITIVE`(긴점박이올빼미, 수리부엉이, 솔부엉이, 올빼미, 팔색조, 황새, 따오기,
호사비오리, 뜸부기, 흰눈썹뜸부기, 검독수리, 뿔쇠오리, 알락쇠오리, 쇠부리슴새)는 정적 페이지의 대표 조류 목록과
설명에서 뺀다. 지도의 공개 자료는 그대로다. 목록은 보수적 기본값이므로 연구회가 검토해 조정한다.
테스트가 정적 페이지에 이 종이 나오지 않음을 검사한다.

## 개인정보·민감정보

- 정적 페이지는 `siteData`의 일반 항목만 쓴다. 좌표, 제보, 현장소식, 제보자 이름, D1 자료는 읽지도 쓰지도 않는다.
- JSON-LD는 `BreadcrumbList`만 사용하며 `geo`·좌표를 넣지 않는다. 테스트가 좌표 패턴·`<script>`(JSON-LD 외)·`fetch`·`workers.dev` 부재를 페이지마다 검사한다.
- 두루미류·저어새·흰꼬리수리 등 겨울철새 보호종은 지명 수준 목록으로 남아 있다(지도와 동일한 공개 정보).
- `robots.txt`는 보안 수단이 아니다. 비공개 자료는 애초에 정적 파일에 넣지 않는다.
- 기존 `share/<id>/` 미리보기 페이지는 `noindex,follow` 만 추가했다(`sites/`와 중복 색인 방지). 공유 링크와 OG 이미지는 그대로 동작한다.

## 중요: robots.txt 위치 한계

크롤러는 **호스트 루트**(`https://wooil1964.github.io/robots.txt`)의 robots.txt만 읽는다.
`/birdmap/robots.txt`는 프로젝트 페이지라 크롤러가 읽지 않는다(해가 없어 요청대로 추가).
따라서 sitemap은 robots.txt가 아니라 **서치 콘솔에 직접 제출**해야 한다.

## 사용자가 해야 하는 일 (배포 후)

1. **Google Search Console**: URL 접두어 속성 `https://wooil1964.github.io/birdmap/` 등록 → 소유권 확인(HTML 파일 업로드 방식: 구글이 주는 `google….html`을 저장소 루트에 두면 됨) → `sitemap.xml` 제출.
2. **네이버 서치어드바이저**: 사이트 등록 → 소유확인(HTML 태그 또는 파일) → 사이트맵 제출. 네이버는 도메인 단위(`wooil1964.github.io`) 등록이라 하위 경로(`/birdmap/`)만 등록되지 않을 수 있다. 이 경우 `wooil1964.github.io` 저장소를 만들어 루트에 인증 파일을 두거나 자체 도메인을 쓰는 방법이 필요하다(서치어드바이저에서 확인 필요).
3. 인증 파일·태그는 발급받은 값이 있어야 하므로 이 PR에 넣지 않았다. 기존 인증 태그는 저장소에 없었다.

검색 순위는 보장되지 않으며, 색인까지 수일~수주가 걸릴 수 있다.

## Cloudflare 비용 영향

실측과 추정을 구분한다. 청구액이 아니다.

- **검색엔진이 정적 가이드 페이지를 방문**: GitHub Pages 정적 파일만 응답. Worker·D1 요청 **0건**.
- **방문자가 지도를 열어 둠 (실측)**: 운영 사이트(`?site=194`)를 탭이 "보이는" 상태로 30초 관찰
  (브라우저 창이 숨겨져 있어 `document.hidden`을 false로 덮어 재현). Worker 요청 16건:
  `reports/public-state` 11건(P1 공개 권한 확인, 코드상 4.75초 간격 = `PUBLICATION_POLL_MS 5000`에서 갱신 여유 250ms 차감),
  `approved`·`pending`·`recent-sites` 각 1건, `field-updates` 2건. 날씨 Worker 1건은 페이지 로드 때 별도.
  탭이 숨겨지면 폴링이 멈춘다(실측 확인).
- **정상 상태 모델**: public-state 약 12.6/분 + field-updates 1/분 + 제보 3종 10분마다(0.3/분) ≈ **14건/분**, 시작 시 약 7건.
  `public-state`는 요청당 D1 단일 행 조회(`WHERE id=1`) 1건이다.

세션당 요청 = 7 + 14 × (탭을 보고 있는 분). 검색 유입 방문자가 **모두** 지도를 연다고 가정한 상한이다.

| 방문자 | 1분 체류(21건) | 3분(49건) | 10분(147건) | 30분(427건) |
|---|---|---|---|---|
| 100명 | 2.1천 | 4.9천 | 1.5만 | 4.3만 |
| 1,000명 | 2.1만 | 4.9만 | 14.7만 | 42.7만 |
| 10,000명 | 21만 | 49만 | 147만 | 427만 |

Workers Paid는 월 1,000만 요청 포함, 초과 100만 건당 $0.30(공시 단가 기준 가정). 가장 큰 칸(1만 명이 30분)도
427만 건으로 포함분의 43%다. 단 **기존 이용 트래픽과 합산**되므로 현재 월 사용량을 대시보드에서 확인해야 하고,
포함분을 넘는 경우에만 초과 요청 × $0.30/백만이 청구된다. D1 읽기는 요청당 소수의 행이라 포함 한도(월 250억 행)에 비해 무시할 수준으로 추정하나
행 수 자체는 측정하지 못했다. Worker·D1 코드는 수정하지 않았다.

## 배포·롤백

- 배포: PR 병합 시 GitHub Pages가 정적 파일을 그대로 서빙한다. 빌드·Worker 변경 없음.
- 롤백: PR을 revert하면 `sites/`, `sitemap.xml`, `robots.txt`, `index.html` 헤드, `share/*` 의 `noindex` 가 함께 원복된다. 이미 서치 콘솔에 제출했다면 sitemap 삭제 후 제거 요청이 필요하다.
- 유의: `index.html` 변경은 `<head>` 메타·JSON-LD와 검색 패널 하단 링크 한 줄뿐이다. 자동 갱신 JSON은 건드리지 않았다.
