# 확인된 별칭의 신규 제보 자동 누적 — 안전 적용 계획

## 동작
- 별도 로그인·인증 없이 기존 제보 입력 방식은 유지한다.
- 기존 **수동 확인 그룹에 속한 승인·이름 공개 동의 제보자 이름**만 별칭으로 인정한다.
- 새 제보는 해당 그룹의 \`created_at\`보다 접수 시각이 **늦고**, 문자·공백이 **정확히 일치**하며, 그 별칭을 소유한 **활성 그룹이 유일할 때만** 기존 \`group:<UUID>\`로 통계를 조회한다.
- 세 가지 이미 등록된 표기 \`행복합니다\`, \`행복합니다김용선\`, \`행복합니다 김용선\`은 각각 기존 확인 그룹에 들어 있을 때만 미래 제보를 자동 누적한다.
- 자동 연결은 **통계 조회 시 계산되는 논리적 귀속**이다. 원본 \`reports\`, 그룹 \`report_ids\`, 감사 기록은 변경되지 않는다. 중복 종은 기존 통계의 집합 계산을 따른다.
- 승인·이름 공개 동의가 없는 제보는 공개 합계에 나타나지 않으며, 보호종·번식·위치 비공개 자료의 **종명 표시 제한은 변경하지 않는다.**
- 이름이 다르거나 여러 그룹이 동일 별칭을 사용하면 자동 합산하지 않는다. 운영자가 수동 검토한다.

## 운영 보안 및 한계
**닉네임은 본인 인증 수단이 아니다.** 제3자가 확인된 별칭을 도용해 제보하면 승인 후 같은 그룹의 통계에 포함될 수 있다. 정확한 사람별 누적 통계를 보장할 수 없다. 운영자가 원본을 검토하며, 이상 징후가 있으면 아래 스위치로 즉시 중단한다.

- 기능 플래그 \`REPORTS_IDENTITY_AUTO_ALIASES=1\`이 **없거나 0이면 기존 동작 유지**.
- \`REPORTS_CONFIRMED_IDENTITIES=1\`도 함께 필요하다.
- 관리자 Worker와 공개 Worker의 **동일한 기능 플래그** 설정이 필요하며, 공개 Worker에서도 다른 기존 설정·바인딩을 보존해야 한다.
- 이 기능은 코드만 변경하며, **새 D1 마이그레이션이 필요 없다.**
- 오류 발생 시 플래그를 0으로 되돌리면 저장한 원본이나 기존 수동 그룹은 그대로 두고 자동 통계 귀속만 즉시 해제된다.
- 기존 PR #94의 수동 추가 연결 기능과 독립적으로 작동한다. 그룹에 실제 ID를 추가하는 기능은 **별도 검증·운영 승인** 후 사용할 것.

## 운영 전 읽기 전용 확인
1. 해당 그룹 27건의 활성 상태와 세 별칭의 공개 여부를 확인한다. 실제 이름을 추측해 입력하지 않는다.
2. 기존 최신 제보 ID 및 접수 시각이 그룹 생성 시각보다 늦은지 확인한다.
3. 다른 활성 그룹에 동일한 별칭이 없는지 확인한다.
4. 자동 기능 OFF에서 현행 공개 그룹 23건·31종 및 관리 27건·33종과 일치하는지 확인한다.
5. 로컬 합성/CI 검증 성공 후 0% 업로드 → 단계적 트래픽 전환에서 비인가 공개, 공개 승인 전 제보, 불필요한 보호종 종명 노출이 없는지 점검한다.
6. 운영 데이터 쓰기 없이 비활성→활성 전환을 진행할 수 있지만, **공개 Worker가 함께 바뀌므로 PR 병합과 배포는 별도 승인 후에만 수행한다.**
