## 3. 항목별 검증 결과

### 3-1. 기준 엑셀·운영 데이터 대조 (요청 1)

- v21·v24 `전국탐조지DB` 각 155행, 운영 229곳 전체를 대상으로 이름 키워드와 거리 비교
- 이름이 걸린 3건은 모두 다른 장소: 교동도·양양남대천(대표종 칸의 "저어새"), 엑셀 21 "동진강 만경강"(김제 하구, 신천습지와 약 38km)
- 12곳 모두 1km 안에 기존 탐조지 없음. 가장 가까운 곳은 남동유수지↔214 송도갯벌 3.5km
- 엑셀에서 가장 가까운 항목도 모두 8km 이상

### 3-2. 신천습지·마동호 독립 좌표 (요청 2)

- 네이버 지도는 내장 브라우저에서 접근이 막혀 쓰지 못함. 대신 OSM 원자료(공식 API `api/0.6/map`)와 구글 지도, 언론 보도로 대조
- **신천습지**: OSM에 같은 이름 점은 없으나, 카카오 점이 OSM 만경강 물길에서 166m, 덕진구-완주군 경계 위에 있음. 보도의 구간 설명과 맞음 → **위치 확인됨**
- **마동호**: 카카오 관리사무소가 OSM 제방에서 93m. 구글 지도의 "마동호" 표시점과 약 630m(호수 표시점이라 대상 차이). 보도의 제방 위치와 주소(보전리) 일치 → **위치 확인됨**
- 한계: 지자체·한국농어촌공사의 공식 좌표 문서는 찾지 못함

## 5. 복구 계획

1. **사전 보관**: 등록 직전 main 커밋 ID, Worker 현재 버전 ID, 운영 D1 `sites` 229행 전체 스냅샷·generation을 기록
2. **Pages**: 병합 커밋을 `git revert -m 1`로 되돌려 Pages 재배포. 229곳 복귀 확인
3. **Worker**: 기록한 이전 버전으로 롤백(`wrangler rollbacks`·버전 배포). 신규 ID 235~246은 미등록 응답, 기존 ID는 정상 응답 확인
4. **D1**: `rollback-registry.sql`로 신규 12행만 제거. 제보·체크리스트가 신규 ID를 참조하면 **중단하고 보고**(데이터 손실 방지). 실행 후 기존 229행 해시가 사전 스냅샷과 같은지 확인
5. **조석·기상 파일**: workflow 재실행으로 재생성
6. **되돌리는 순서**: D1 → Worker → Pages(등록의 반대 순서)

2. 12곳 대표종·계절의 최신 근거 부족(공통 조건)
3. 동림저수지·소매물도 통제 기간 미확인
4. 조석 4곳 API 지원 미검증
5. 신천습지·마동호는 공식 기관 좌표 문서 대신 OSM·구글·보도로 확인
