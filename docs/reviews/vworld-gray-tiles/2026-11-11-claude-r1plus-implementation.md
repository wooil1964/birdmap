## 1. 작업 목적

일부 타일만 실패한 화면에서 실패 칸이 회색으로 남는 문제를 고친다.
- 원인: Leaflet은 실패 타일을 다시 요청하지 않고, 컨트롤러는 부분 실패 배치를 완료로 보고 마감 타이머를 해제한다.
- 해결: 실패 칸만 제한적으로 다시 요청한다. 요청량 제한(429)을 악화시키지 않는다.

## 3. 변경 내용(`assets/birdmap-basemap.js`)

| 항목 | 동작 |
|---|---|
| 대상 | 주 레이어(일반·위성)의 **현재 화면** 안 실패 칸만. 하이브리드 지명 레이어는 이번 범위 밖(지명 누락은 회색이 아님) |
| 첫 대기 | 60 s + 0~15 s 지터. 이미 타이머가 돌고 있을 때 새로 본 실패 칸은 한 라운드 더 기다림(항상 60 s 이상) |
| 라운드 | 레이어당 라운드 타이머 1개. **카나리 1칸**이 성공하면 나머지를 **2칸씩**, 라운드당 최대 8칸. 하나라도 실패·취소되면 그 라운드 종료 |
| 칸별 백오프 | 칸마다 최대 4회. 간격은 1·2·4·8 라운드(약 60/120/240/480 s). **시계가 아니라 라운드 수로 셈** → 시험에서 시간 조작이 쉬움. 이후에는 회색과 안내 유지 |
| 실행 조건 | 배치 진행·줌 휴식·줌 애니메이션 중이면 건너뜀(그 배치 끝에 다시 예약). 숨김 탭이면 한 라운드 뒤로 미룸. 마지막 라운드 뒤 지도가 움직였으면 750 ms 정지 후 실행 |
| 판정 | 재시도 칸의 성공·실패는 배치 집계(`batchSuccesses`/`batchErrors`)에 넣지 않음 → **재실패가 OSM 전환·잠금을 일으키지 않음** |
| 마감 12 s | 남은 미응답이 재시도 칸뿐이면 OSM으로 바꾸지 않고 부분 안내 유지 |
| 안내 | `partial_error`를 배치 오류 수만이 아니라 **현재 화면의 실패 칸**으로도 판단. 다른 배치가 성공해도 회색이 남아 있으면 안내 유지 |
| 정리 | `detachVworld()`(종류 변경·OSM·설정 변경·destroy 경로)에서 타이머·집합 초기화. 콜백마다 세대 토큰·레이어 동일성(`current`) 확인. `destroy()`에서 `movestart` 해제 |
| 상태 API | `getState().partialRetryPending` 추가(진단용, 비밀값 없음) |
| 요청 방식 | 실패 칸을 `_removeTile`로 지우고 Leaflet `_update()`가 같은 URL로 다시 만들게 함. 쿼리 문자열 없음(Worker는 쿼리가 있으면 404). `no-store`라 실제로 재요청됨 |

보존한 기존 동작:
- 장애 판정식(3장 이상·성공보다 많음)
- 12 s 무활동 마감(새 칸 기준)
- 60/120/240/480 s 종류별 복구와 90% 복귀 기준
- 배치 번호(`failLater`)와 `later()` 지연
- 줌 정착(400~900 ms)과 idle 배치 닫기
- 지명 레이어 독립 판정
- "다시 시도" 버튼의 동작과 노출 조건(UI 변경 없음)

## 6. 기존 기능 영향 여부

- 정상 화면: 실패 칸이 없으면 새 타이머·요청이 없다.
- 전면 장애(전부 429·502, 무응답): 기존 OSM 전환·복구 경로 그대로. 부분 재시도가 끼어들지 않는다(설계 검증 T7·T8).
- 요청량 증가: 실패한 칸 수만큼이다.
  - 지속 429·영구 실패에서는 레이어당 약 60 s에 1건이고, 칸당 4회 뒤 멈춘다.
  - 지금까지는 사용자가 OSM↔위성을 눌러 화면 전체(24~48장)를 다시 받는 것이 유일한 복구였다.
- 화면 표시: 재시도 배치 동안 상태 문구가 잠깐 "불러오는 중"으로 바뀔 수 있다(기존 배치와 같은 표시).

## 7. 발견된 미해결 문제

**운영에서 확인하지 못한 것**
- 최초 실패 원인(429·502 비율), 리미터 현재값과 창 방식, Cloudflare 일일 사용량. 배포 전 7일 기준선이 필요하다.

**실제 환경에서 시험하지 못한 것**
- 실기기(Android·iOS)와 실제 핀치는 미확인이다.

**설계상 남겨 둔 것**
- 하이브리드 지명 레이어의 부분 실패는 재시도하지 않는다.
- 부분 실패에서 기존 "다시 시도" 버튼은 보이지 않는다. UI 변경이라 별도 승인 대상이다.
- 지터는 이용자 간 동시 파동을 줄이려는 것이지 전역 리미터 포화 자체를 해결하지는 않는다.
- Leaflet 1.9.3 내부(`_tiles`·`_removeTile`·`_update`)에 의존한다. Leaflet 업그레이드 때 다시 검증해야 한다.

**롤백**
- 이 커밋의 파일 3개를 되돌리고 Pages를 재배포하면 된다. Worker·데이터 변경은 없다.
- 롤백 조건은 설계 검증 문서 10장에 있다.
