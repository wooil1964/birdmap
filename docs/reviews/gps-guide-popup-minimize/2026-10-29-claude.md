# GPS 안내 중 출현종 위치 카드 최소화 — Claude Code 작업 보고

- 작업 도구: Claude Code (Codex 작업 인수, 단독 수정)
- 기준 커밋: main `a2698e0` (PR #54 병합)
- 작업 브랜치: `fix/gps-guide-popup-minimize-20261029`, PR #55

## 1. 작업 목적
모바일에서 출현종 위치 카드의 **내 위치 찾기** 성공 뒤 큰 흰 카드가 지도 중앙에 남아 파란 점·안내선·직선거리를 가리는 문제를 해결한다. GPS 안내 기능과 공개 목적지 검증은 그대로 유지한다.

## 2. 확정 원인 (확정)
| 경로 | 팝업 | PR #54 접힘 |
|---|---|---|
| 탐조지 상세 (`data-location-site`) | 모바일 하단 시트 `.birdmap-mobile-popup` | 적용 |
| 일반 출현 지점 마커 (`data-location-report`) | 모바일 하단 시트 | 적용 |
| 공개 고정 붉은 점 (`data-location-fixed`) | 모바일 하단 시트 | 적용 |
| 탐조지별 출현 이력 종명 · 최근 제보 15건 | `.birdmap-report-location-popup` 카드 (`_birdmapReportLocation`) | **미적용** |

`birdmap-basemap-init.js`의 `presentPopup()`은 `_birdmapReportLocation` 카드를 하단 시트로 바꾸지 않는다. `birdmapCollapseMobilePopupForGps()`는 `.birdmap-mobile-popup`만 접으므로 이 카드에서는 `false`를 돌려주고 아무것도 하지 않았다. `fit()`도 카드를 하단 여백으로 계산하지 않았다. 기존 브라우저 회귀(`popup-regression.cjs`)는 이 경로에서 안내 활성만 확인했다.

재현(현재 main 자산 + 새 검사, 390×844): 카드 높이 180px, 화면 y 283~463, `dotCovered:true`, `labelCovered:true`.

## 3. 변경 사항
- `assets/birdmap-species-search.js/.css`: 모바일에서 검증된 안내가 그려지면 카드를 최근 제보 목록 바로 위의 **위치 안내 중 · 정보 보기 · ×** 막대로 접는다. 팝업·제보 ID 검증·닫기 이벤트는 유지(`map.closePopup()` 미사용). **정보 보기** ↔ **접기** 전환. 안내 종료·위치 지우기·닫기·공개 상태 변경 시 막대를 제거하고 원래 카드로 복원.
- `assets/birdmap-location.js`: `focusGuide()` — 그려진 안내만, 목적지 유효성 재확인 후 접기 + 지도 맞춤. 새 GPS·공개 API 요청 없음. collapse/restore를 팝업 종류별로 분기. `fit()`·GPS 도구 배치에 접힌 막대를 하단 장애물로 추가.
- `assets/birdmap-basemap-init.js`: 모바일 시트도 안내 중 **펼치기** 뒤 **접기**로 안내 화면 복귀. 안내 종료 시 버튼을 **펼치기**로 복원.
- 시험: `test_gps_location.mjs`에 `focusGuide` 단위 시험, `popup-regression.cjs`에 경로별 접힘·비가림·반복·복원 검사. 합성 제보 지점 id를 실제 `/reports/approved` 구조(지점 id = 첫 제보 id)에 맞춤.
- 변경 없음: `index.html`, `siteData` 229곳 좌표, Worker·D1·Access·비밀값, 기상·조석 파일.
