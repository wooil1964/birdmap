## PR 및 CI 원칙

현재 통합 브랜치 하나를 푸시하고 main 대상 통합 PR 하나를 만든다. PR 이벤트가 기존 필수 CI를 자동 시작하게 하며, 중복 workflow_dispatch는 하지 않는다. CI의 실제 최종 HEAD·결과·실패 원인은 후속 전달 보고서와 Actions에서 확인한다. CI 실패 시 관련 결함만 수정하고 보안 조건과 검사 범위를 유지한다.

이번 단계에서는 **main 병합·운영 Worker/Pages 배포·스위치 활성화를 하지 않는다**. PR #79도 닫거나 병합하지 않는다.

## 별도 운영 승인 후의 배포 순서

1. 승인한 PR SHA, 현재 public/admin Worker 버전, Pages 서비스 커밋과 D1 복구용 읽기 백업을 기록한다. 기존 PR #78/v2 보호가 있는 이전 public/admin/Pages 조합과 CI의 protective Pages artifact를 복구 후보로 확보한다. 배포 전 검증된 HEAD와 실제 승인 SHA가 같아야 한다.
2. 자동 공개/미검증 읽기는 계속 OFF로 둔다. 배포 창에는 REPORTS_PUBLIC_READS_CLOSED=true로 동적 공개 읽기를 닫고, 필요하면 보호용 Pages를 먼저 적용한다. 새 D1 마이그레이션이나 원본 보정은 필요하지 않다.
3. **public/admin Worker를 한 세트로 먼저 배포**하고 peer/release·canonical mode·writer fence·스위치를 확인한다. 중간 버전 불일치는 비공개/503으로 닫혀야 하며 방어 조건을 우회하지 않는다. 승인된 배포 설정과 실제 release 조합을 기록한다.
4. 검증된 통합 PR의 main 병합으로 Pages가 자동 반영되는 설정인지 먼저 확인한다. 자동이라면 **Worker 준비 전에 main 병합하지 않는다**. 같은 승인 SHA의 Pages를 반영한 뒤 projection/권한 계약, 승인 이력·검색·개체수·가림 좌표·길찾기를 확인한다.
5. 공개/관리자/Pages가 모두 일치하고 보호·철회 검사가 통과한 뒤 읽기 폐쇄만 해제한다. 두 자동 공개 스위치는 OFF 그대로다. 자동 공개 활성화는 별도 승인·시험이다. 통합 병합 성공을 확인한 뒤 중복 PR #79를 정리한다.
