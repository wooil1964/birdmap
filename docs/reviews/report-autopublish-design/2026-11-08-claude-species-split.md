## 1. 구조 조사 결과 — 기존 구조 재사용, D1 마이그레이션 없음

| 필요 사항 | 사용한 기존 구조 |
|---|---|
| 한 제보 ID 유지 | `reports.id` = `checklists.checklist_id` 그대로 |
| 원본 보존 | `reports.species`, `raw_submissions.payload_json`(수정 금지 트리거), `sightings.species_original`(수정 금지 트리거) |
| 종별 국명 | `sightings.species_identified` (종마다 1행, `source_ordinal`) |
| 종별 개체수·미입력 구분 | `sightings.count_value`, `count_source`(`reported` / `not_recorded` / `ambiguous_group`) |
| 종별 검증 상태 | `sightings.interpretation`(`single` / `unknown` / `unparsed_multiple`), `interpretation_note` |
| 종별 수정 이력 | `reviews`(`sighting_id`, `validated_count`, `corrected`) — 기존 관리자 처리 경로 |

기존 자료와의 구분: 지금까지 저장된 행은 `species_identified`가 모두 비어 있다. 그래서 통계·검색·지도는 "식별 국명이 있으면 그것, 없으면 기존 원문"으로 처리한다. **기존 승인 133건은 다시 분류되지 않는다.**

## 2. 분리 규칙

- 인정하는 형식: `국명` 또는 `국명 + 숫자 (+ 마리|개체)`. 즉 `동박새3` = `동박새 3` = `동박새 3마리` = `동박새 3개체`.
- 숫자 규칙: 1 이상, 앞자리 0 없음, 10만 이하. 숫자가 없으면 개체수 미입력(`null`, `not_recorded`)이며 1로 보지 않는다.
- 한 종만 쓰고 숫자를 생략하면 양식의 개체수를 그 종에 쓴다(기존 규칙). 텍스트 숫자와 양식 개체수가 다르면 불확실로 둔다.
- 같은 종 두 번(`동박새3, 동박새5`): 두 행 모두 `unknown` / `duplicate_species`로 두고 개체수는 합산하지 않는다. 종수는 1종이다.
- 하나라도 형식에 맞지 않으면 기존처럼 원문 1행으로 저장하고, 자동 공개하지 않고 관리자 검토로 보낸다(`species_parse`). 예: `3동박새`, `동박새 3 5`, `동박새 03`, `동박새 0`, `동박새3마리2`, `동3박새`, `Zosterops 3`, `동박새 3쌍`, `동박새 1000000`.
- 관리자 정정(승인 시 종명 수정): 종별 행을 순서대로 다시 맞춘다. 원문은 그대로 두고, 행이 모자라면 추가하고, 남으면 `superseded`로 무효 처리한다. 종별 이력은 `reviews`에 남는다.

## 3. 결과 예시 (시험으로 확인)

| 입력 | 저장(sightings) | 종수 | 개체수 | 자동 공개 |
|---|---|---|---|---|
| `동박새3, 박새2, 직박구리1` | 동박새 3 · 박새 2 · 직박구리 1 | 3 | 6 | 적격 |

## 4. 통계·검색 일관성 (시험으로 확인)

| 위치 | 처리 |
|---|---|
| 관리자 통계 요약 | 종수 = 식별 국명 기준(`동박새3`·`동박새5` → 1종). 개체수(`individuals`)와 개체수 집계 대상 제보 수(`counted_reports`)를 따로 둠 |
| 관리자 종별·제보자별 통계 | 종별 개체수 합(중복·미입력 제외). 종 필터도 식별 국명으로 찾음 |
| 관리자 카드 | `종별: 동박새 3개체 · 박새 2개체 · 쇠딱다구리 (개체수 미입력) — 3종, 개체수 5(입력분)`. 중복은 `(개체수 확인 필요)`, 1종 |
| 회원별 공개 통계 | 종수·종 목록이 식별 국명 기준(제보 4건 → 5종, 기존 `고니3`은 그대로) |
| 검색·지도·탐조지 이력 | 신규 자료는 수량 없는 국명으로 표시(`동박새` 검색 시 3건). 기존 자료 표시는 그대로 |
| 미검증·확인 완료 구분 | 생태 통계와 공개 통계는 확인 완료(approved)만 사용. 미검증은 들어가지 않음 |

## 7. 남은 사항·정책 결정 필요

- 기존 자료 보정은 하지 않았다. 필요하면 별도 계획으로 진행한다. 제안: 관리자가 종명을 다시 저장하면 그 제보만 구조화되므로(이번 구현), 일괄 보정은 "분리 후보 목록 → 관리자 확인" 방식이 안전하다. 운영 D1 일괄 UPDATE는 권하지 않는다.
- 공개 화면에는 종별 개체수를 표시하지 않는다(종명만). 공개 여부는 정책 결정이 필요하다.
- 개체수 합은 "보고된 값의 합"이다. 서로 다른 제보가 같은 무리를 셌을 수 있다.
- 공식 국명 확인(`taxa` 연결)은 하지 않았다. 국명 형식(한글)과 허용 목록 일치만 확인한다. 시범 18종 목록은 확정 정책이 아니다.
