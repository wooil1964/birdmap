## 6. 하루 자동 공개 한도 동시성 수정

- **누적 건수 정의:** 같은 날(KST) "자동 공개"로 판정되어 저장된 접수 판정 기록을 센다(`reviews` seq 1, `system:auto-public`, `auto_public:auto-public-v1`). 관리자가 나중에 공개 중지·승인·반려해도 줄지 않는다. 판정과 저장 확인이 같은 정의를 쓴다.
- **저장 batch 안 확인:** 자동 공개로 판정된 접수만, 판정 기록 INSERT 뒤에 `assertion(…)`을 넣는다. 조건은 "오늘 건수 ≤ 한도 그리고 같은 IP 건수 ≤ 5"다. D1 batch가 한 트랜잭션이므로, 늦게 확정되는 접수는 이 확인에서 실패하고 batch 전체가 롤백된다.
- **실패 처리:** 재전송·CAPTCHA 재사용·중복 확인 뒤, DB에서 어느 한도가 찼는지(`global_cap` / `rate_review`) 확인해 `AUTO_PUBLIC_CAP_RACE`로 올린다. 접수 처리기가 같은 요청을 **검토 대기로 한 번만** 다시 저장한다. 사유는 재판정 사유와 DB에서 확인한 한도 사유를 합친다. 제보를 버리거나 거절하지 않는다.
- **유지되는 것:** 기존 스팸 방지 제한(같은 IP 10분 5건·하루 20건, 429)은 그대로다. 스위치 OFF이면 확인 문장이 batch에 들어가지 않아 현행과 같다.
