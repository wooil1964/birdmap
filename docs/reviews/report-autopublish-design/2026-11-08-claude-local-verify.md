### 3.3 보호종·희귀종·근거 부족 차단 (독립 보안 행렬)

이 시험은 분류 코드를 거치지 않는다. DB 행과 검토 기록을 직접 꾸민 17개 사례를 넣고, 공개 GET 7종 + 상태 조회(strict·legacy)만 보고 판정한다.

- 사례: 과거 플래그만 있는 행, 보류 판정 행, 다른 정책 버전, 관리자 판정 기록, 판정 순번 불일치, 다른 결정값, 보호종, 보호종 혼합, 희귀종, 모르는 종명, "참새?", 번식 메모, 번식 종명, 개체수 이상, 만료, 공개 중지, 반려
- 결과: 세 스위치 상태 모두 좌표 노출 0
- 양성 대조군: 정상 일반종은 보인다. 위치 가리기 대조군은 실제 좌표가 없고 공개점이 1 km 이상 떨어져 있다.
- 12회 반복 실행: 모두 안정

변이 검사(사본에서 실행, 변이당 2회):

### 3.4 관리자 승인·반려·복원 (관리자 Chrome 34건 + 서버 시험)

- 확인 완료(승인) → 승인 자료로 이동하고 미검증 목록에서 빠짐

- 반려(오동정) → 비공개, 감사 이력 `reject:misidentification`
- 반려 후 재승인
- 확인 완료분 공개 취소 → 대기·비공개
- 검토 대기 제보 위치 가리기
- 과거 플래그 행 → "검토 대기"로 표시되고 공개되지 않음
- 보호종 보류 사유 표시

## 5. 이번 검증에서 고친 결함

1. **종명 뒤 수량 표기가 개체수 상한을 우회**함(`참새 5000마리` 적격). 합의한 "개체수 이상 → 보류" 요구사항 위반이었다. 종별 상한을 적용하도록 고쳤다.
2. **읽기 스위치 OFF일 때 재전송 접수증이 `public_unverified`로 응답**함(좌표 없음). M7 변이 검사로 발견했다. 재전송 경로에도 스위치 확인을 넣었다.
3. 시험 코드: `test_publication_rollout.mjs` 문법 오류, 보안 행렬 시험의 불안정성(문자열 비교 → 거리 판정).

종별 개체수 분리와 통계 반영은 설계서·권장안에 없던 기능이다. 지시("새 기능 추가 금지")에 따라 구현하지 않았다. 구현하려면 접수 시 종별 `sightings` 분리, 통계의 수량 표기 제거, 기존 승인 자료를 재계산하지 않는 범위 확정이 필요하다(정책 결정 필요).

## 7. 미확인 위험과 추가 확인 필요

- GitHub CI 미실행(관리자 승인 대기). 로컬에서 실행하지 않은 CI 단계: miniflare D1 펜스, Pillow 공유 카드 2건
- 보호종 목록은 잠정본(공식 고시 대조 안 함). 안전성은 허용 목록(18종)이 보장한다(M8 증거).
- 18종 목록 전문가 검토 전
- 운영 배포 시 projection 전환 공백(약 1~2분, PR #78 실측 기준). 관리자 Worker도 함께 배포해야 새 화면이 쓰인다.
- 하루 상한은 판정 시점의 개수 조회라 동시 접수 시 1~2건 초과 가능(코드에 표시)
- IP별 상한은 단위 시험(가짜 DB)으로만 확인했고, 실제 IP를 쓴 통합 시험은 없음(시험 도우미가 요청마다 다른 IP를 씀)
- 실기기(휴대폰) 화면 미확인
