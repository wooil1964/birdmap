## 0. 요약

- **상태값을 새로 만들지 않습니다.** 기존 `pending` / `approved` / `rejected`와 기존 열 `pending_public`, 기존 `reviews` 감사 표를 그대로 씁니다. **D1 마이그레이션이 필요 없습니다.**
- "자동 공개 · 미검증"은 `status='pending'` + `pending_public=1` + **서버가 남긴 자동 공개 판정 기록(reviews)**의 세 가지를 모두 갖춘 제보입니다. 공개 API는 **읽을 때마다 분류 규칙을 다시 적용**합니다. 그래서 과거에 남은 `pending_public=1` 값이나 관리자가 바꾼 내용만으로는 공개되지 않습니다(fail-closed).
- 자동 공개 대상은 **허용 목록(allowlist) 방식**입니다. 승인된 "자동 공개 일반종 목록"에 정확히 있는 종만 자동 공개합니다. 보호종 목록·희귀종 검토 목록·이름 미확정·이상 개체수·중복 의심은 모두 **보류**입니다.
- 기능 스위치 두 개를 둡니다. `REPORTS_AUTO_PUBLIC`(신규 자동 공개)와 `REPORTS_UNVERIFIED_READS`(미검증 공개분 노출). 둘 다 끄면 **현재 사전 승인제와 똑같이** 동작합니다.
- 통계·주간 추천·제보자 기여 통계는 **확인 완료(approved)만** 씁니다. 지도와 검색에는 미검증 표시를 붙여 노출합니다.
- PR은 하나, CI는 PR을 열 때 1회를 목표로 합니다. 배포는 "스위치 끔 상태로 배포 → 동일성 확인 → 소수 종으로 켬 → 확대"의 순서입니다.

## 2. 권장 통합 아키텍처

### 2.1 상태 모델: 기존 값 재사용

새 상태값을 만들지 않는 이유:
- `pending`을 "아직 관리자 확인 전"으로 계속 쓰면, 통계·추천·기여자·이력처럼 `approved`만 읽는 경로가 **자동으로 미검증분을 제외**합니다. 반대로 `approved`를 자동 공개에 쓰면 모든 통계 경로에 미검증 자료가 섞입니다. 그것을 막으려면 경로마다 수정해야 합니다.
- 마이그레이션 없이 배포·롤백할 수 있습니다.

**"자동 공개 · 미검증"의 조건(세 가지 모두 충족):**
1. `reports.status='pending'` 이고 `pending_public=1`
2. `reviews`에 `decision='submitted'`, `actor_id='system:auto-public'`, `reason_code='auto_public:<정책버전>'` 행이 있음. 이 행은 접수 묶음 안에서 함께 기록됩니다.
3. **읽는 시점에** 현재 정책으로 분류를 다시 해도 "공개 적격"

조건 2가 있으므로 과거의 `pending_public=1` 흔적이나 예전 관리자 Worker의 `visibility` 조작만으로는 공개되지 않습니다. 조건 3이 있으므로 관리자가 종명을 보호종으로 정정하거나 허용 목록에서 종을 빼면 **즉시 비공개**가 됩니다.

### 2.2 표시 상태 (DB 상태와 분리)

화면 표시는 아래 표대로 **계산**합니다. 저장하지 않습니다.

| 표시 상태 | status | pending_public | 추가 판별 |
|---|---|---|---|
| 자동 공개 · 미검증 | pending | 1 | 자동 공개 기록 있음 + 재분류 적격 |
| 자동 공개 중지(재검사 불통과) | pending | 1 | 자동 공개 기록 있음 + 재분류 부적격 (관리자에게만 보임) |
| 검토 대기 · 비공개 | pending | 0 | 마지막 검토 기록이 보류 또는 없음 |
| 공개 취소 | pending | 0 | 마지막 검토 기록이 `unpublished` 또는 관리자 비공개 처리 |
| 확인 완료 | approved | (무관) | |
| 반려 · 비공개 | rejected | (무관) | |

### 2.3 제보 상태 전이표

| 현재 표시 상태 | 사건 | 다음 상태 | reviews 기록 | 공개 영향 |
|---|---|---|---|---|
| (없음) | 접수 + 자동 판정 적격 + 스위치 켬 | 자동 공개 · 미검증 | `submitted` / `system:auto-public` / `auto_public:v1` | 지도·검색에 미검증으로 표시 |
| (없음) | 접수 + 부적격 또는 스위치 끔 | 검토 대기 · 비공개 | `submitted` / `system:auto-public` / `hold:<사유들>` | 없음 |
| 자동 공개 · 미검증 | 관리자 확인(승인) | 확인 완료 | `approved` | 확인 완료 마커(기존 붉은 점), 통계 반영 |
| 자동 공개 · 미검증 | 관리자 정정 후 승인 | 확인 완료 | `approved` (+정정 내용) | 정정 결과로 v2 적용 |
| 자동 공개 · 미검증 | 관리자 반려(사유) | 반려 · 비공개 | `rejected` + 사유 코드 | **즉시 제거** (revision 증가 → 화면 정리) |
| 자동 공개 · 미검증 | 관리자 공개 중지 | 공개 취소 | `corrected` / `visibility_off` | 즉시 제거 |
| 자동 공개 · 미검증 | 정책·목록 변경으로 재분류 부적격 | 자동 공개 중지 | 기록 없음(읽기 계산) | 즉시 제거 |
| 검토 대기 · 비공개 | 승인 | 확인 완료 | `approved` | 공개 |
| 검토 대기 · 비공개 | 반려 | 반려 · 비공개 | `rejected` | 없음 |
| 확인 완료 | 공개 취소 | 공개 취소 | `unpublished` | 제거 |
| 공개 취소 | 재승인(복원) | 확인 완료 | `approved` | 공개 |
| 반려 · 비공개 | 재승인 | 확인 완료 | `reapproved` | 공개 |

- **미검증으로 되돌리는 복원은 두지 않습니다** [결정 필요, 권장안]. 복원은 "확인 완료(승인)"로만 합니다. 그래야 관리자가 한 번 내린 판단을 자동 판정이 덮어쓰지 않습니다.
- 사용하는 결정값은 모두 기존 `reviews.decision` CHECK 안에 있습니다 [확인].

### 2.4 기능 스위치

| 스위치 | 끔(0) | 켬(1) |
|---|---|---|
| `REPORTS_AUTO_PUBLIC` | 신규 제보 전부 "검토 대기"(현재와 동일) | 분류 적격이면 자동 공개 |
| `REPORTS_UNVERIFIED_READS` | 미검증 공개분 전체를 공개 응답에서 제외 | 조건 충족분만 노출 |
| `REPORTS_AUTO_PUBLIC_DAILY_MAX` | — | 전체 하루 자동 공개 상한(초과분 보류) |

두 스위치를 끄면 현재 운영과 같습니다. 스위치별로 미리 올려 둔 Worker 버전(0% 대기)으로 **수 초 안에 전환**할 수 있습니다. 기존 `REPORTS_PUBLIC_READS_CLOSED` 긴급 차단도 그대로 유지합니다.

## 3. 자동 분류 정책 (일반종·희귀종·보호종)

### 3.1 원칙

- **허용 목록만 자동 공개합니다.** 목록에 없는 이름은 일반종으로 간주하지 않습니다(fail-closed).
- 목록은 셋으로 **따로** 관리하고 버전을 붙입니다.
  1. `auto-public-common` — 자동 공개 허용 일반종. 관리자 승인 필요
  2. `protected-legal` — 법정 보호종(멸종위기 야생생물 I·II급, 천연기념물 조류). 위치 노출 위험 기준
  3. `rare-review` — 희귀종·미조·동정 혼동종. 동정 검증 기준
- 같은 종이 1번 목록과 2·3번 목록에 함께 있으면 **보류가 우선**합니다. 빌드 시험에서 겹침 자체를 실패로 처리합니다.
- 기존 위치 정책 v2의 19종 목록은 **바꾸지 않습니다**. 2번 목록은 자동 공개 관문에만 씁니다(§6 충돌 분석 참고).

### 3.2 종명 처리

| 항목 | 기준 |
|---|---|
| 기준 국명 | 한국조류학회 「한국 조류 목록」 최신판 [결정 필요: 판·연도 지정. 미확인] |
| 정규화 | NFC, 앞뒤 공백 제거, "종명 + 숫자(마리/개체)" 꼴의 수량 표기 분리(기존 방식 재사용) |
| 동의어 | `synonyms` 표(관습명·구 국명 → 기준 국명)만 인정. 부분 일치·유사도 일치는 쓰지 않음 |
| 복수 종 | 구분자로 나눈 **모든** 토큰이 허용 목록에 있어야 자동 공개. 하나라도 불명이면 제보 전체 보류 |
| 종 수 상한 | 한 제보 5종 초과 시 보류 [결정 필요: 상한 값] |
| 미확정 표현 | "?", "추정", "~류", "sp." 등이 있으면 보류 |

### 3.4 위치 가리기

제보자가 위치 가리기를 고르면 접수 때 만든 대략점(1.5~4.5 km 이동, 1회 생성, 기존 방식)만 공개합니다. 자동 공개 여부와는 별개입니다.

### 5.3 중복·재전송·원자성

- 접수의 자동 판정과 `reports`·정본·원자료·`reviews(submitted)` 기록은 **같은 batch**입니다. 판정만 남고 저장이 실패하거나 그 반대인 경우는 없습니다.
- 재전송(같은 `request_id`)은 기존 `replayQuick`이 현재 행 상태로 접수증을 다시 계산합니다. 미검증 공개 여부도 현재 상태 기준이라, 그 사이 반려된 제보가 접수증에서 "공개"로 보이지 않습니다.
- 관리자 처리는 기존 CAS(revision) + 요청 ID 재전송 보호를 그대로 씁니다.
- 하루 상한·IP별 상한은 판정 시점의 카운트 조회입니다. 동시 접수로 상한을 1~2건 넘을 수 있습니다 [추정]. 이를 막으려면 batch 안에 조건부 assertion을 넣습니다(기존 `assertion()` 방식 재사용).
