### 3.2 리미터 실제 설정
- 배포 도구에 고정된 값:
  - `CLIENT_TILE_LIMITER`: namespace `[공개본 마스킹]`, limit 180, period 60
  - `GLOBAL_TILE_LIMITER`: namespace `[공개본 마스킹]`, limit 300, period 60
- 10/25 점검의 "relay" 상태 판정은 두 binding의 namespace·limit·period가 위 값과 같아야 통과하며, 통과로 기록됐다(**기록상 확정**).
- `vworld-tiles/src/worker.mjs` 232~233행: IP 키(접속 IP)를 먼저, 전역 키(`birdmap-vworld-base`)를 그다음에 검사한다. 둘 다 같은 `429 tile_rate_limited`를 돌려준다(확정). 응답만으로는 어느 쪽이 거절했는지 알 수 없다.
- 공식 문서(Workers Rate Limiting): period는 10 또는 60초. 제한은 Worker가 실행되는 Cloudflare 위치별이고, 위치끼리 합산하지 않는다. 계산은 근사이며 다른 인스턴스에 사후 동기화되므로 설정값을 넘는 요청이 통과할 수 있다. 엄격한 단일 제한에는 Durable Objects를 권한다. 대시보드에는 binding이 표시되지 않는다.
- 현재 값 재조회: 미확인.

### 3.3 운영 중계 경로
- 코드·문서(확정): 브라우저 → Worker → 서울 Lambda 함수 URL → `api.vworld.kr` WMTS.
  - Worker 단계: Origin/Referer 확인, 타일 범위 확인, 리미터, SigV4 서명.
  - Lambda 함수 URL: 인증 방식 AWS_IAM, Node.js 22, arm64, 128MB, 제한 10초.
  - 시간 제한: Lambda 안 VWorld 호출 6초, Worker의 중계 호출 8초.
  - Worker는 키 대신 중계 주소와 호출 전용 IAM 사용자 키를 비밀값으로 갖고, VWorld 키는 Lambda에만 있다(`vworld-relay/README.md`).
- 기록: 10/25 중계 전환·키 삭제 후 점검에서 3계층 30/30, 실행 위치 `remote-ICN`. 10/26 Lambda 동시 실행 한도 1000(예약 없음) 적용 후 재활성화, 운영 PC·모바일 점검 통과.
- 현재 실제 경로: 미확인(이번에 요청을 보내지 않음).

### 3.4 Cloudflare 요청량·429·시간대 분포 — 미확인
- 접근 권한이 없어 읽지 못했다.
- HTTP 429 정확한 건수는 Workers Logs/Logpush가 있어야 보이는데, 둘 다 꺼져 있다(3.1). 이번 작업에서는 활성화가 금지라 켜지 않았다.
- 대신 쓸 수 있는 지표(공식 문서): Analytics GraphQL `workersInvocationsAdaptive`의 `requests`, `subrequests`, `errors`(스크립트별·시간별). `status` 차원은 호출 상태이지 HTTP 상태가 아니다.
  - 허용된 타일은 Lambda로 하위 요청을 1번 보내고, 429·403·404·503은 보내지 않는다. 따라서 "요청 − 하위 요청"으로 거절 규모를 추정할 수 있다.
  - 이 값은 429만 따로 세지 못하는 추정치다.
- 과거 관측(10/27, 1회 측정·2회 재현): 한 IP에서 13~14초 동안 651·702건 요청, 60초 창 약 680건째에 첫 429. 요청이 들어온 콜로는 HKG였다.

### 3.5 Lambda 호출량 — 미확인
- 접근 권한이 없어 읽지 못했다.
- Lambda 호출 수는 Worker가 통과시킨 타일 수에 가깝지만, 429 건수를 확정하는 데는 쓸 수 없다. 429는 Lambda까지 오지 않고, 서명 실패도 호출로 집계되지 않기 때문이다. 비교 지표로만 쓴다.

### 3.6 지역별 근사 방식의 영향
- 문서상 카운터는 "Worker가 실행되는 위치" 기준이다.
- **추정:** 이 Worker는 서울 지정 배치로 실행된다(기록상 `remote-ICN`). 그렇다면 대부분의 호출이 한 위치에서 세어진다. 이 경우 전역 리미터 300/60초는 사실상 모든 사용자 합계에 대한 제한처럼 작동할 수 있다. PC 사용자 두세 명이 동시에 빠르게 탐색하면 다른 사용자까지 429를 받을 수 있다는 뜻이다. 배치와 리미터 위치의 관계는 공식 문서에서 명시적으로 확인하지 못했다.
- 반대로 근사·사후 동기화 때문에 짧은 순간에는 설정값보다 훨씬 많이 통과할 수 있다(10/27 관측). 그래서 실제 체감 한도는 시점과 부하에 따라 달라진다.

### 3.7 VWorld 이용 약관 (공식 사이트 확인, 2023-08-18 시행본)
- 제13조: 운영기관은 모든 인증키에 대해 전송량과 호출 횟수를 제한한다. 구체적인 제한용량은 별도로 공지한다. 초과하면 그 키를 쓰는 서비스가 중단될 수 있고, 초과 이용은 신청해야 한다. 같은 조에서 운영기관 동의 없는 영리 목적 이용을 금지한다.
- 제19조: 오픈플랫폼이 제공하는 데이터는 사전 승낙 없이 저장할 수 없다.
  - Worker의 `no-store`는 이 조항과 맞는다.
  - 브라우저·엣지 캐시 허용은 승낙 없이는 선택지가 아니다.
- 구체적인 키별 한도 수치: **미확인.** 오픈API 안내, 저작권정책 페이지와 이전 조사의 FAQ에서 찾지 못했다. 로그인 후 인증키 관리에서 보일 가능성이 있다.
- 개정 약관: 2026-10-30 효력이라고 공지돼 있다(사전 공지 9/29~10/29). 세부는 첨부 PDF(현행·개정·신구조문대비표)에만 있다. 파일 내려받기는 승인이 필요해 열지 않았으므로 **미확인**이다.

## 7. 미확인을 채우기 위한 읽기 전용 확인 방법 (사용자 수행 또는 권한 제공)

1. **Cloudflare**(VWorld 전용 계정, 읽기 전용 단기 토큰: Workers Scripts 읽기, Account Analytics 읽기)
   - 스크립트 설정 조회로 binding(리미터 namespace·limit·period)과 배치·관측 설정을 확인한다. 대시보드에는 리미터가 보이지 않는다.
   - 배포·버전 목록으로 활성 버전을 확인한다.
   - Analytics GraphQL `workersInvocationsAdaptive`로 최근 7~14일 시간별 `requests`·`subrequests`·`errors`를 읽고, 차이로 거절 규모를 추정한다.
   - 토큰은 확인 후 바로 삭제한다.
2. **AWS CloudShell**(읽기 전용)
   - CloudWatch `AWS/Lambda`에서 해당 함수의 `Invocations`·`Errors`·`Throttles`·`ConcurrentExecutions`를 시간별로 확인한다.
   - **주의:** 함수 설정 조회 명령은 환경변수(VWorld 키)를 그대로 출력한다. 반드시 출력 필드를 런타임·메모리·제한시간 등으로 제한해야 한다.
3. **VWorld**
   - 로그인 후 인증키 관리에서 키별 사용량과 제한용량이 보이는지 확인한다.
   - 공지 첨부 PDF(개정 약관, 신구조문대비표)에서 호출량·저장·캐시 관련 변경을 확인한다.
