## 실제 근거와 재현

이전 Work 작업의 실제 outputs/PR95-운영검증결과.md, work/smoke.mjs, expected.mjs, expected.json과 작업 실행 기록을 읽었다. 실제 실패 표기는 종명 끝에 ASCII 작은따옴표가 붙은 호사비오리'다. 원본 제보나 실제 민감 좌표는 이 문서/시험에 복사하지 않았다. 당시 smoke는 reporter-stats와 reporter-species만 점검했으며, 기대값을 같은 정책 함수로 계산해 비교하는 것만으로 보호 정책의 정확성을 검증하지 못했다. 별도 보호명 비노출 확인에서 실패해 두 후보를 제거했다.

main과 PR95 HEAD의 shared.js·publication.js가 동일함을 대조했다. 실제 실패 문자열을 입력한 수정 전 reporterSpeciesNames 로컬 재현 결과는 species 배열에 원문이 남고 restricted=false였다. isLocationRestricted도 false였다. 새 운영 노출을 유발하지 않은 로컬 함수 재현이다. 전체 운영 D1에서 이 표기의 건수/위치/다른 제보자 영향을 전수 조사한 결과는 아니다.

## 원인

1. 공통 isSensitiveReport의 기존 목록은 19종이었다. 호사비오리는 별도 protected-birds.js의 법정 보호 목록에는 있지만 이 공통 목록에는 없었다. 정확한 표기도 공통 위치/종명 판정에서 누락되는 정책 분리가 있었다.
2. splitOfficialSpecies는 공식 국명을 완전히 해석하는 경우만 분리한다. 끝 작은따옴표 표기는 원문 토큰으로 남았다. isProtectedSpeciesToken은 정확 일치/수량/이름 식별만 검사했고, 식별 실패를 false로 반환했다. 미확인 표기가 공개 허가로 흘렀다.
3. legacySpeciesItems/speciesNamesOf는 미해석 원문을 보존해 반환한다. 관리자·통계 원문 보존에 필요하지만, reporterSpeciesNames의 허용 기본값과 결합해 원문을 공개했다.
4. 기존 isLocationRestricted는 유효한 비번식 확인이면 보호 판정을 건너뛰었다. 검색은 제한 행도 종명 자체는 남기고 위치만 가렸다. 요청된 비공개 우선 정책과 맞지 않았다.
5. PR95의 별칭 자동 연결은 취약 판정의 최초 도입이 아니다. 신규 승인 자료가 그룹 조회에 포함되며 문제를 드러낸 촉발 조건이다. 그룹 계산 자체는 수정하지 않는다.

## 수정

- shared.js에서 기존 19종과 저장소 법정 보호 이름/연결 국명/지도 민감종을 공통 공개 정책에 사용한다. 공식 국명·법정 목록 자료 자체는 수정하지 않는다.
- 기존 parseSpeciesItems와 identifyBird를 재사용한다. 구분자·공백으로 완전히 해석되면 각 종을 검사한다. 문장부호·괄호·불확실 표기를 임의 삭제하거나 접두사/부분 문자열을 일반종으로 구제하지 않는다. 하나라도 식별 불가이면 행 전체를 비공개로 닫는다. 일반종의 장식 표기도 비공개가 될 수 있다.
- 원문, 구조화된 식별 종명, 공개 개체수 DTO 종명을 모두 검사한다. 일반종 식별값으로 민감 원문을 덮어쓰는 우회를 막는다.
- 비번식 확인과 관리자 승인은 보호종·미확인 종명의 공개 허가가 아니다. 번식 상태 판정과 원자료 검증 자체는 유지한다.
- 검색은 제한 행을 검색/합계/페이지 계산 전에 제외한다. 일반종 위치 가리기·이름 공개 동의는 기존대로 적용한다.
- 자동 공개 접수에도 보호 관문을 적용해 첫 접수 응답과 재전송/GET의 비공개 판정을 일치시킨다.
- 비활성 현장소식의 번식 전용 검사는 hasBreedingEvidence를 명시적으로 호출한다. 빈 종 배열을 넣어 공통 보호 판정을 번식 검사처럼 쓰던 결합만 제거한다. 운영 현장소식 폐쇄(410)는 유지한다.
- 승인 상태, 원문, 좌표, siteData, 그룹 계산·report_ids, DB 스키마/마이그레이션은 변경하지 않는다. 공개 통계 건수는 기존 정의를 유지하며 종명 목록은 보수적으로 줄어든다.
