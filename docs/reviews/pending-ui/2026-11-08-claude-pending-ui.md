# 자동 공개 제보 화면 연결 (로컬)

기준 main 0126392, 브랜치 claude/pending-ui-20261108. PR·CI·병합·배포·운영 D1 변경 없음.

## 변경
1. **마커**: 자동 공개 제보를 승인 제보와 같은 붉은 출현 마커(`#d32f2f`, 같은 크기·투명도·pane)로 그린다 (`index.html` birdmapPendingMarker). 팝업·툴팁의 기존 자동 공개 표시는 그대로.
2. **최근 출현 제보 목록**: 승인 기록(`reportSearchIndex`)과 `/reports/pending` 이 내려준 자동 공개 제보를 합친 `recentReportEntries()` 로 그린다. 관찰일 최신순(같은 날은 종명), 60일·15건 제한 그대로. 같은 id 가 승인되면 중복 없이 승인 쪽만.
   - 검색 색인(`reportSearchIndex`)에는 넣지 않았다(종 검색·보관함은 승인 자료만).
3. **클릭 이동**: 목록 줄을 누르면 해당 자동 공개 마커로 이동하고 팝업을 연다(`openReportEntry` 가 `pending` 종류 처리). 위치 가림 건은 공개된 대략점으로 이동. 승인 줄은 기존(공개 제보 위치 카드) 그대로.
   - 목록 줄의 날짜·이름 줄을 붙이는 `assets/birdmap-basemap-init.js` 와 줄 클릭을 가로채는 `assets/birdmap-species-search.js` 도 합친 목록 순서를 쓰도록 맞췄다(둘 다 승인 색인의 순서만 가정해서, 그대로면 날짜가 엉뚱하게 붙고 자동 공개 줄이 눌리지 않았다).
4. **제보자 이름**: 공개에 동의한 제보만 표시한다. `/reports/pending` 응답(`reports-api/src/autopublic.js`)에 승인 제보와 같은 규칙으로 `reporter` 를 추가했다(`name_public=1` 이고 이름이 있을 때만; 아니면 필드 자체가 없다). 화면은 그 이름을 글자 그대로(텍스트) 표시하고, 없으면 익명이다. 메모·실제 좌표·내부 상태는 여전히 내보내지 않는다. 이 변경은 **공개 Worker 배포가 필요**하다.
5. **노출 범위**: 서버가 `verified:false` 로 내려준 공개 자료만 사용. 검토 대기·공개 중지·반려는 응답에 없으므로 나타나지 않는다. 관리자 상태·감사 이력 변경 없음.
6. **안내문 최소 수정**(`index.html`): 제보 창 상단 "관리자 확인을 거친 뒤에만 지도에 표시됩니다…" → "제보하신 내용은 접수 즉시 지도에 표시될 수 있습니다. 번식 관련 제보이거나 확인이 필요한 제보는 관리자 확인 뒤에 공개됩니다."; 위치 가리기 설명의 "승인 후에도" 삭제. 새 배지·미검증 안내 추가 없음.
7. 위치 가림, 정책 v2, 200 m 중복, 개체수, 길찾기 코드는 건드리지 않았다.

## 남은 위험
- 동의하지 않은 자동 공개 줄은 모바일에서 "익명 제보"로 보인다(기존 줄 장식 규칙).
- 팝업·툴팁에 기존 "미검증" 표시가 남아 있다(요청 범위 밖이라 유지).
- 운영 반영은 Pages 배포(병합) + 공개 Worker 새 버전(이름 필드)이다. Worker 없이 Pages만 먼저 나가도 이름만 비어 있을 뿐 동작은 같다.
