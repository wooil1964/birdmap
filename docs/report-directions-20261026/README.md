- 두 진입 경로(최근 제보 15건 / 탐조지 최근 이력)의 공통 작은 팝업에 카카오맵·티맵 버튼을 복구한다. 기존 220px 본문/모바일 카드 폭, 한 줄의 버튼 2개, 각 44px 높이, 사진 없는 본문을 유지한다.

- 고정 마커에 연결된 제보는 공개 고정 마커 위치이며 실제 관찰 지점이 아니라는 안내와 목적지 이름을 사용한다.

## 외부 연결 근거와 제약

카카오맵은 [공식 웹 가이드](https://apis.map.kakao.com/web/guide/#routeurl)의 https://map.kakao.com/link/to/이름,위도,경도 방식을 재사용한다. PC 카카오맵 페이지와 모바일 applink 목적지까지 확인했다.

[티맵 공식 Invoke 길안내 문서](https://tmapapi.tmapmobility.com/main.html#webv2/sample/webSample61)는 모바일 앱 호출과 앱키가 필요한 HTTPS 호출을 설명한다. 공식 PC 웹 길찾기/휴대폰 전달 방식의 근거는 확인하지 못했다. 새 앱키나 설정은 추가하지 않고 기존 tmap://route?goalname=...&goalx=경도&goaly=위도 함수를 재사용한다. PC에서는 티맵 버튼이 보이며 기존 스마트폰 전용 안내를 표시하고 앱 전용 주소를 실행하지 않는다. 기존 스킴의 실기기 앱 실행을 공식 HTTPS Invoke의 지원 보증으로 간주하지 않는다.

카카오 서비스가 모바일 applink로 좌표를 변환하면서 소수점에 미세한 재투영 차이가 생기지만 원 요청 좌표는 마커와 정확 일치한다. 지도 중심은 Leaflet의 화면 픽셀 반올림 오차 1px 이내를 허용하고 외부 링크 좌표는 정확 비교한다.

**실기기 Android/iOS의 카카오맵·티맵 앱 실행은 미검증이다. 이 환경에서는 연결된 휴대폰/원격 실기기를 찾지 못했다. 브라우저 모의를 실기기 성공으로 보고하지 않는다. 실기기 확인과 필수 CI 통과 전에는 병합·Pages 운영 배포를 보류한다.**

Safari의 비동기 권한 확인 후 새 창/앱 호출 허용도 실기기 확인이 필요하다. 새 창 차단 시 안내를 표시한다.
